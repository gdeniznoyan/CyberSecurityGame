# Cybersecurity Architecture Builder

Cybersecurity Architecture Builder is a browser-based educational game for constructing and analysing remote-access architectures. It is written with HTML, CSS and strict TypeScript. It uses no UI framework and has no runtime dependency.

The application is not a security-control checklist. A component contributes to the result only when it is placed, configured and connected on an actual path from a user or client device to a reachable resource.

## Where Everything Is Implemented

- `index.html` contains the page shell, controls, canvas host, toolbox host, analysis sidebar and import/export dialog.
- `css/style.css` contains the complete responsive visual design.
- `src/types.ts` defines all shared TypeScript contracts.
- `src/areas.ts` defines the six architecture zones.
- `src/components.ts` defines all 38 components as individual objects.
- `src/state.ts` owns placements, directed connections and configuration values.
- `src/evaluator.ts` discovers the active access path, derives effective properties, detects openings, classifies the architecture and calculates the secondary score.
- `src/renderer.ts` creates the canvas, toolbox, connection editor, configuration controls and analysis output.
- `src/dragDrop.ts` handles drag-and-drop, click placement, connection actions, removal and configuration changes.
- `src/main.ts` starts the application and wires analysis, reset and JSON import/export.
- `dist/` contains JavaScript and source maps generated by TypeScript. Do not edit it manually.

## Run and Build

Install development dependencies:

```powershell
npm install
```

Compile TypeScript:

```powershell
npm run build
```

Watch for TypeScript changes:

```powershell
npm run watch
```

The browser loads `index.html`, which imports `dist/main.js` as an ES module. Serve the project with any local static web server when browser security rules prevent module loading directly from disk.

## How to Use the Builder

1. Drag a component from the toolbox into its compatible architecture zone. A component can also be selected and then placed by clicking a compatible zone.
2. Choose `Connect` on a source component and `Link` on its destination. Connections are directed.
3. Choose `Configure` on components that expose behavioural options.
4. Continue the path until a user or client device can reach a resource.
5. Read the automatically updated classification, score and causal analysis.
6. Use `Export Current State` to copy the placements, connections and configurations as JSON.
7. Use `Import State` to restore a valid exported architecture.
8. Use `Reset` to remove the complete architecture state.

## Important Design Rules

- Architecture classification is more important than the numerical score.
- A high score cannot force a Saytec Post-Zero Trust result.
- Only properties effective on the discovered access path affect classification.
- A component outside the path is not treated as active protection.
- External systems matter only when the connected path depends on them.
- Network-level exposure overrides weaker claims of application isolation.
- Removing a component also removes every connection and configuration owned by it.
- Every state change automatically rerenders and reevaluates the architecture.
